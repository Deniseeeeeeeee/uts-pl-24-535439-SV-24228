2. Log Laravel ke stdout/stderr

Image backend memakai php:8.2-apache (mod_php), bukan php-fpm. Pada mod_php, PHP berjalan di dalam proses Apache sehingga php://stderr langsung menjadi stderr container. Pada php-fpm hal ini tidak otomatis: output worker dibuang kecuali catch_workers_output = yes dan error_log = /proc/self/fd/2 diaktifkan. Di image ini juga error.log Apache sudah diarahkan ke /dev/stderr. Bukti: variabel log aktif dan folder storage/logs kosong.

Alasan memilih alur yang diberi log

LevelAlurAlasan
INFOSimpan / ubah / hapus film Operasi yang mengubah data. Log menjadi jejak audit: siapa (user_id) mengubah film mana (movie_id) dan field apa saja, sehingga perubahan atau kehilangan data bisa ditelusuri. Isi data tidak dicatat, cukup id dan nama field.
WARNINGValidasi input gagal (login & film) Bukan kesalahan server, tetapi sinyal yang perlu diawasi: lonjakan di /api/login bisa berarti percobaan brute force, dan lonjakan di /api/movies bisa berarti bug di frontend. Yang dicatat hanya nama field dan rule yang gagal, bukan nilainya, karena nilai bisa berisi password atau email.
ERRORGagal konek ke database Penyebab paling umum seluruh API gagal (HTTP 500). Harus langsung terlihat dan bisa dikaitkan dengan status unhealthy. Pesan QueryException sengaja tidak dicatat karena memuat SQL beserta binding (misalnya email saat login); yang dicatat hanya pesan PDO, misalnya getaddrinfo for db failed.

Healthcheck service app

  app:
    # P10: Docker memanggil GET /health di dalam container.
    # /health membalas 503 kalau DB/cache gagal -> curl -f keluar non-zero -> unhealthy.
    healthcheck:
      # Saat DB mati, lookup DNS "db" masih butuh ~5 detik, jadi batas curl 8 detik.
      test: ["CMD", "curl", "-fsS", "--max-time", "8", "http://localhost/health"]
      interval: 10s
      timeout: 10s
      retries: 3
      start_period: 40s

Healthcheck service frontend & db

  frontend:
    # wget sudah tersedia di image nginx:alpine (BusyBox)
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://127.0.0.1/"]
      interval: 15s
      timeout: 5s
      retries: 3
      start_period: 10s
  db:
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -u root -p$$MYSQL_ROOT_PASSWORD --silent"]
      interval: 5s
      timeout: 5s
      retries: 30
      start_period: 20s

8. Kesimpulan

Log aplikasi kini keluar ke stderr dalam format JSON sehingga bisa dibaca lewat docker compose logs app dan dirotasi oleh driver json-file (maks 3 × 10 MB per service). Endpoint /health benar-benar memeriksa DB dan cache, membalas 503 dengan komponen yang gagal tanpa crash, dan dipakai Docker sebagai healthcheck sehingga status container berubah menjadi unhealthy saat DB mati lalu kembali healthy otomatis setelah DB dinyalakan.
